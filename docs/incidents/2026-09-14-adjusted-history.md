# 액면병합 후 저장된 Naver 수정주가의 기준 불일치

## 원인

`price_basis=adjusted`는 수집 시점까지의 수정주가라는 의미였지만, 이후 기업행동에서도
재계산이 필요 없는 값으로 취급됐다. 대교(019680/019685)와 더라미(032860)에서 확인했다.
주식수 스냅샷 누락 때문에 기업행동 탐지 날짜가 실제 거래 재개일보다 늦을 수 있고,
천 주 단위 Naver 주식수로 산출한 비율에는 소수점 오차도 있다.

## 수정

- 정규 일일·전체 빌드에서 기업행동 변경 종목의 전체 Naver 수정주가를 다시 받는다.
- 원천 캡처는 Bronze에 해시별로 보존하고, 재계산용 스냅샷은 별도 Silver에 보관한다.
- 기존 Naver 날짜 누락·빈 응답·중복 날짜·유효하지 않은 종가·최근 기업행동 주변의
  큰 가격 단절은 실패로 처리한다. 실패 시 기업행동 적용 완료 상태로 전진하지 않는다.
- Gold는 원천에서 다시 확인한 날짜의 OHLCV를 사용한다. 이미 갱신된 가격에
  추정 기업행동 비율을 다시 곱하지 않는다. 원본 Silver 가격은 보존한다.
- 이전 Gold의 전일 종가와 해당 날짜 전체 종목을 보존하는 기존 품질 검사를 유지한다.

## 복구 도구

```bash
.venv/bin/python scripts/refresh_action_prices.py --tickers 019680,019685,032860
.venv/bin/python scripts/refresh_action_prices.py --tickers 019680,019685,032860 --apply
```

Linux의 정규 `pipeline.lock`을 사용한다. 기본은 미리보기이다. `--apply`는
영향받는 모든 Gold 파티션을 `_state/action-refresh-<시각>/backup/`에 복사한 다음
날짜별로 원자적으로 반영한다. 각 날짜의 다른 종목 행과 종목 집합은 보존한다.
가격 변경 후 preferred_discount 파생 테이블도 다시 빌드하고 공개 API를 확인해야 한다.

미리보기에서 3종목 18,430행 중 종가가 변경되는 행은 18,361개였다.
대교 8월 13일은 2,000원/1,196원, 더라미 8월 28일은 3,450원이다.
대교 9월 10일과 11일 실제 종가는 변하지 않는다.

## 운영 반영 결과

- `action-refresh-20260914-085610`에서 7,264개 가격 파티션을 백업하고 반영했다.
- 3종목 18,430행의 전체 OHLC가 원천 재조회 결과와 일치하고 중복은 0건이었다.
- 71개 날짜를 표본 검사해 다른 종목 197,365행이 백업과 동일함을 확인했다.
- preferred_discount도 백업 후 755,531행(9,469개 파티션)을 재생성했고,
  카탈로그 36개 뷰를 갱신했다. admin 서비스 재시작 후 API 가격을 확인했다.
- 반영 후 재조회 미리보기 `action-refresh-20260914-090023`의 추가 변경은 0행이다.
- 운영 Python 테스트 355개가 통과했다. GitHub CI에서 발견된 기존 스크리너 테스트의
  UTC/한국 날짜 차이는 한국 날짜를 고정하는 테스트로 수정했다.
- 두 소비 대시보드의 배포가 성공했고, 공개 히스토리·전체 지표·요약 데이터와
  바이오스마트 현재가 산출물이 검증한 로컬 결과와 모두 일치했다.

별도로 9월 11일 정규 실행에서 Naver 구형 종목목록 페이지가 새 도메인으로
302 이동하면서 summary 수집이 실패한 상태를 확인했다. 최신 가격은 9월 11일이지만
이는 기업행동 가격 복구와 별개이며 `/api/ready`의 실패를 임의로 성공 처리하지 않는다.
